# v0.4 — Organizational Designs for AI Co-scientists

## Research framing

The next paper does not ask only whether one technical architecture is better than another.

It asks:

> **How does organizational design shape collective reasoning and decision quality in AI co-scientists?**

The same CSRP evidence base will be organized in three different ways. The evidence substrate should remain matched; the organizational form is the experimental treatment.

---

## Architecture A — Functional Multi-Agent Organization

```text
                    FacilitatorAgent
                           |
       ---------------------------------------------
       |           |          |          |          |
Perspective     Predict    Strategy   External   Decision
  Agent          Agent      Agent      Agent      Agent
       \           |          |          |         /
        -------- Shared CSRP Evidence -------------
```

All role agents can access the same retrieved evidence, but each role is assigned a distinct information-processing function.

- **PerspectiveAgent** — maps populations, methods and viewpoints.
- **PredictAgent** — summarizes observed directions/uncertainty; later can support bounded forecasting tasks.
- **StrategyAgent** — considers intervention options, applicability and limitations.
- **ExternalAgent** — brings in setting, transferability and external-context considerations.
- **DecisionAgent** — integrates the role outputs.
- **FacilitatorAgent** — coordinates the sequence and final synthesis.

**Management-theory lens:** Organizational Information Processing Theory (OIPT), functional differentiation and Contingency Theory.

---

## Architecture B — Paper-Agent Committee

```text
Paper 1 -> PaperAgent 1 --\
Paper 2 -> PaperAgent 2 ---\
Paper 3 -> PaperAgent 3 ----> CommitteeChair -> Final decision
...                         /
Paper N -> PaperAgent N ---/
```

Each retrieved paper becomes an isolated PaperAgent. It first represents only its own paper's evidence. A chair/facilitator then aggregates the reports; the later LLM implementation can add structured rounds of discussion, challenge and rebuttal.

This architecture deliberately preserves private paper-level contexts so we can test whether explicit expert-style deliberation helps or hurts as the number of papers grows.

**Management-theory lens:** Transactive Memory Systems, group decision making, information aggregation, coordination cost and Contingency Theory.

---

## Architecture C — Shared-Knowledge Umbrella Organization

```text
Paper 1 -> Skill 1 --\
Paper 2 -> Skill 2 ---\
Paper 3 -> Skill 3 ----> Shared Registry + Evidence Graph
...                    /                 |
Paper N -> Skill N ---/                  v
                               Institutional Orchestrator
                                         |
                              Evidence Judge + Safety
                                         |
                                  Final synthesis
```

Papers do not become persistent agents. They remain shared evidence/capability objects. The institutional reasoning layer draws multiple skills into one shared workspace.

**Management-theory lens:** Knowledge-Based View, OIPT, modular organization and Contingency Theory.

---

## Main theoretical proposition

The paper should avoid assuming that one architecture is universally optimal.

A stronger management-science proposition is:

> **The performance of an AI co-scientist depends on the fit between organizational structure and task information-processing requirements.**

Candidate moderators:

- task interdependence;
- task uncertainty;
- evidence load;
- evidence heterogeneity.

This naturally leads to an **Architecture × Task Characteristics** experimental design.

## Experimental principle

Keep constant across all three architectures:

- corpus;
- query set;
- retrieval policy;
- evidence budget;
- base LLM and model version;
- sampling settings;
- maximum context/output budget;
- tool access;
- retry policy.

Vary only the organizational structure and coordination pattern.

## Candidate dependent variables

- cross-paper relation accuracy;
- decision quality;
- evidence coverage;
- citation/provenance precision and recall;
- contradiction vs qualification reasoning;
- unsupported-answer / hallucination rate;
- coordination messages;
- token cost;
- latency.

## Current implementation boundary

The v0.4 code is a **deterministic organizational scaffold**. It makes the three context/coordination structures runnable and inspectable, but it is not yet the matched LLM experiment.

The next implementation step is a provider-neutral LLM adapter and a fixed retriever/evidence budget shared across the three organizations.
