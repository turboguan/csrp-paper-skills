# v1.3 — Three-Architecture Flagship Case

## Purpose

Before spending API budget on the full 36-cell mini-pilot, run **one identical suicide-prevention policy case through all three active architectures**.

This is the first direct end-to-end check of the revised comparison:

1. Functional Virtual Institute
2. Minimal Virtual CSRP
3. Shared-Knowledge Umbrella

## Flagship question

> Given the short-term positive intervention evidence, the longer-term New Taipei findings, implementation limitations, and the regional observational context, should a suicide-prevention policymaker consider restricting retail access to barbecue charcoal? Provide a concise evidence memo covering supporting evidence, limiting evidence, implementation conditions, uncertainty, transferability, and remaining evidence gaps.

The task is deliberately difficult enough to require cross-paper synthesis but narrow enough to inspect manually.

It combines:

- short-term intervention evidence;
- longer-term follow-up;
- implementation limitations;
- possible method substitution;
- regional observational context;
- transferability and policy uncertainty.

## Matched design

The evidence retriever runs **once**.

All three architectures receive the exact same EvidencePacket and the same:

- four-paper corpus;
- evidence budget;
- model/version;
- total token ceiling;
- decoding settings;
- query;
- safety boundary.

Organizational structure is the treatment.

## What we inspect before the 36-cell pilot

We are not looking for a winner yet.

We check whether:

- each architecture actually behaves differently;
- all three stay inside the same evidence boundary;
- provenance survives synthesis;
- limiting and supporting evidence are both represented;
- uncertainty is explicit;
- the policy bottom line is conditional rather than universal;
- coordination/token differences are measurable.

## Human review

The output is exported in blinded form. Reviewers score:

- evidence correctness;
- cross-paper synthesis;
- uncertainty handling;
- policy usefulness;
- provenance quality;
- unsupported claims.

Architecture identities are stored separately.

## Decision rule for proceeding

Proceed to the 36-cell mini-pilot only if:

1. all three architectures complete successfully;
2. the EvidencePacket is identical across architectures;
3. no architecture systematically loses provenance because of an implementation bug;
4. the outputs are meaningfully distinguishable in process or result;
5. the review rubric can be applied without ambiguity.

This flagship run is a **diagnostic system check**, not a scientific result.
