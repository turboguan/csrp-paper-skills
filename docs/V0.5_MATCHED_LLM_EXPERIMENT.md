# v0.5 — Matched LLM Experiment Infrastructure

## What is now matched

For each benchmark query, the experiment runner now enforces four shared components across the three organizational architectures:

1. **One LLM adapter / one fixed model ID**
2. **One retriever executed once per query**
3. **One evidence-paper budget**
4. **One total token budget and decoding configuration**

The same retrieved `EvidencePacket` is distributed to all three organizations. Architectures are not allowed to re-retrieve or silently change the paper set.

## Architectures

- `functional_multi_agent`
- `paper_agent_committee`
- `shared_knowledge_umbrella`

## Budget policy

The initial scaffold uses:

- evidence papers: 4
- total token ceiling per architecture-query cell: 16,000
- maximum output per LLM call: 700
- maximum calls: 8
- temperature: 0.0
- seed: 42 where supported

These are provisional engineering values. Freeze final values before the first real benchmark.

## Important fairness choice

We do **not** force every architecture to use the same number of LLM calls.

That would erase a genuine property of organizational design. Instead:

- all organizations receive the same total token ceiling;
- call count is measured as an outcome;
- coordination-heavy architectures may spend their budget across more calls;
- shared-context architectures may spend it in fewer calls.

This permits a direct quality–coordination-cost comparison.

## Provider-neutral adapter

`LLMAdapter` defines:

- `count_tokens(messages)`
- `generate(messages, max_output_tokens, temperature, seed)`

`CallableLLMAdapter` can wrap any real provider/client while preserving one model ID and token-accounting contract.

`DeterministicTestLLMAdapter` exists only for offline CI and must never be reported as model performance.

## Fixed retriever

`FixedEvidenceRetriever` executes once per query and creates an immutable `EvidencePacket`. The packet records:

- retriever ID;
- evidence budget;
- exact paper IDs.

Every architecture must return the exact same paper IDs or the matched runner raises an error.

## Token accounting

Each architecture gets a fresh `LLMRuntime` with the same `MatchedBudget` but the same underlying adapter/model.

The runtime records:

- input tokens;
- output tokens;
- total tokens;
- LLM calls;
- model ID;
- budget configuration.

A run fails if an architecture exceeds the configured total-token or call budget.

## Current boundary

The infrastructure is ready, but **no real provider/model has been selected or benchmarked yet**.

The next step is to choose one fixed model/version, connect it through `CallableLLMAdapter`, freeze the final experiment config, and run the same benchmark questions across all three organizational designs.
